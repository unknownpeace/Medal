# Gateway Architect Skill

Specialized knowledge and operational runbooks for Linux transparent gateways, sing-box TUN engines, and AdGuard Home integration.

## Core Architectural Principles

1. **TUN Inbound Architecture (sing-box 1.11+):**
   - Use `type: "tun"`, `interface_name: "tun0"`, and `inet4_address: "172.19.0.1/30"`.
   - Use `auto_route: true` and `strict_route: false` (to prevent SSH management lockouts on physical interfaces).
   - **Never** include deprecated fields like `gso: true/false` (causes runtime crashes in modern sing-box).
   - Set `sniff: true` and `sniff_override_destination: false` for protocol and SNI detection.
   - For Clash API integration, bind to `0.0.0.0:9090` and configure external UI path.

2. **nftables Gateway Table (`inet homelab`):**
   - Always implement atomic table replacement to prevent rule accumulation during reloads:
     ```nftables
     table inet homelab
     delete table inet homelab
     table inet homelab { ... }
     ```
   - In `output` chain: bypass packets generated by proxy processes using `meta skuid` or socket marks to eliminate user-space routing loops.
   - In `prerouting`: redirect incoming port 53 (TCP/UDP) from clients to `:53` (AdGuard Home). Drop port 853 (DoT) with TCP reset to force clean fallback.
   - In `forward`: enforce TCP MSS clamping (`tcp flags syn tcp option maxseg size set rt mtu`) to prevent MTU packet drops across WAN and TUN.

3. **AdGuard Home & Clean DNS Pipeline:**
   - Client queries port 53 (AdGuard Home) -> AdGuard Home enforces ad/tracker blocking -> forwards upstream to `127.0.0.1:1053` (sing-box Fake-IP) or direct DoH/DoT resolvers.
   - **Crucial Setting:** `aaaa_disabled: true` must be enabled when IPv6 is disabled at kernel level (`net.ipv6.conf.all.disable_ipv6 = 1`). This prevents musl/glibc DNS transient timeout errors.
   - Cache size in AdGuard Home should be disabled (`cache_enabled: false` or `cache_size: 0`) when paired with Fake-IP engines to prevent cache desync.

4. **Network Modes (Gateway vs Router):**
   - **Mode 1 (Gateway / Прозрачный шлюз):**
     - Operates alongside existing home router (Keenetic, OpenWrt).
     - **DHCP in AdGuard Home MUST be disabled** (`dhcp.enabled: false`).
     - NAT masquerading active on `eth0` and `tun0`.
   - **Mode 2 (Router / Домашний роутер):**
     - Operates as primary router (WAN on `eth0`, LAN/Wi-Fi on `wlan0`/`eth1`).
     - **DHCP in AdGuard Home MUST be enabled** (`dhcp.enabled: true`).
     - Dynamic subnet pool calculation (`${IP_PREFIX}.50` to `${IP_PREFIX}.250`).
     - Static reservations for `.1` and `.5` to protect upstream hardware from collision.

## Step-by-Step Troubleshooting Runbook

1. **Verify Kernel Forwarding & BBR:**
   ```bash
   sysctl net.ipv4.ip_forward net.ipv4.tcp_congestion_control net.ipv4.ip_unprivileged_port_start
   ```
2. **Check nftables Active Ruleset:**
   ```bash
   nft list table inet homelab
   ```
3. **Verify sing-box TUN & Route:**
   ```bash
   ip addr show tun0
   curl -s http://127.0.0.1:9090/configs
   ```
4. **Test Transparent Routing:**
   - Russian direct site: `curl -sI https://ya.ru` (should be fast, DIRECT).
   - Foreign blocked site: `curl -sI https://www.youtube.com` (should return HTTP/2 200 via PROXY).
